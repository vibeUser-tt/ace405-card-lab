# Gothenburg 建筑竞标实验室 · 入门 POC

用卡牌修改建筑参数，观察采光、运行能耗与方案成本。三个委托分别强调采光、能耗、成本。朝南、两层、Gothenburg 固定，八个变量无槽位，参数跨轮保留。

## 运行与验证

Node.js 22.12+（验证环境 24.11）：

~~~text
npm run dev
npm test
npm run build
npm run balance -- --runs=2000 --offset=30001 --tag=reproduction
npm run test:ui
~~~

浏览器测试默认连接 http://127.0.0.1:5173，可通过 POC_URL 指定本地地址。本次预览使用 4180。报告与截图位于 validation/。

## 参数与卡牌

| 变量 | 游戏档位 | 单张行动 |
|---|---|---|
| 正面窗墙比 | 20 / 30 / 40% | ±10 个百分点 |
| 窗套深度 | 0.50 / 0.75 / 1.00 m | ±0.25 m |
| 外墙 U | 0.150 / 0.225 / 0.300 | ±0.075 |
| 屋顶 U | 0.10 / 0.15 / 0.20 | ±0.05 |
| 地面 U | 0.13 / 0.19 / 0.25 | ±0.06 |
| 热回收率 | 0 / 30 / 60% | ±30 个百分点 |
| 玻璃 | U0.90 / SHGC50% / 透光70%；U1.80 / SHGC60% / 透光75% | 成套切换 |
| 每人新风量 | 4 / 7 L/s | ±3 L/s |

U 值单位为 W/(m²·K)。游戏只使用这些粗档位，评估器支持区间内数值。共 2916 种标准配置。16 种设计牌、7 种功能牌，牌名包装设计行动，下面只写本次参数变化（如“热回收率 +30%”），上下限显示在双方建筑参数格，不预告采光或能耗收益。百分比牌按数值直接加减，例如30%加30%得到60%。出牌后显示实际 D/E/C 前后值；对手每轮全部操作、无变化原因和更新轮次均有记录。

## 当前规则

- 每轮恢复4体力，手牌补至5，上限8。设计牌消耗2体力，可反制牌对自己和对手同费；取消自调、反制、功能牌三类次数限制，可自由连续出牌。
- 功能牌按牌面费用支付。「针对性干扰」同样为2体力；额外抽牌最多4张、额外回能最多2点、体力储量最多5点、保留最多2张仍为卡牌效果规则，用于避免免费循环。「短时冲刺」花1回2，净增加1体力。
- 成套方案牌仅用于自己，目前为「保温玻璃」「通透玻璃」；其余14张增减参数牌可用于自己或对手。牌面标明“仅自身”或“可反制”。普通反制、AI、强化和针对性干扰共用此范围。越界截断；边界无变化也可出牌，正常消耗卡牌和体力。
- 成本由当前完整方案决定，不累计出牌费用。可以超预算；获胜时须同时满足 D/E/C 三项门槛。
- 功能牌包括抽牌、换牌、体力、保牌、干扰、强化、防护。没有免费换牌；「聚焦优化」撤下。
- 「针对性干扰」选择削减采光或增加能耗，从可反制的增减参数中选择对该指标作用最大的调整，不更换对方玻璃。遵守同样边界，成本与其他指标一起重算；无有效调整时正常打出但不改变建筑。不存在直接扣竞标分。
- 「二次施压」使下次参数反制重复一次，也适用于针对性干扰；需有可反制牌及足够体力，只有玻璃牌时不能激活，已反制过也可继续强化。「方案防护」抵挡选定变量的一次反制，持续至自己下次行动前；玻璃不受反制，不列为防护目标。再次防护会替换保护变量，不叠加；干扰不会绕开被保护的首选变量重新选目标。
- 双方行动后评审：一方达标则获胜；双方同轮达标比综合分，再比更低成本，完全相同则平局。上限内均未达标为未完成。

| 委托 | sDA 最低 | 年能耗最高 | 成本最高 | D/E/C 权重 | 回合上限 |
|---|---:|---:|---:|---|---:|
| 让光进来 | 50% | 155 | 95 | 65/20/15 | 40 |
| 温暖而节制 | 50% | 140 | 105 | 15/65/20 | 32 |
| 恰到好处 | 50% | 145 | 90 | 15/25/60 | 40 |

初值按委托设置，并与对手相同：采光关从 20% 窗墙比、0.75m 深度开始；能耗关已有 30% 热回收；成本关从部分高配的方案开始（外墙中档、热回收 30%）。完整初值在 src/model.ts。综合分将 D 的 20→70、E 的 200→100、成本的 130→38 映射至 0→100 并截断，按委托权重求和；高分不能替代达标门槛。

## 数据与可视化

src/gothenburg.json 来自 AR 项目 256 个 ORI0_NoF0 组合。scripts/extract-gothenburg.py 是只读提取入口，记录原始文件哈希。D 为所有房间传感点等权汇总的 sDA（DA≥50 的点数比例）；E 为全年 heating、cooling、hot_water、equip、lighting 总和，沿用 kWh/(㎡·年) 口径，不是 Primary Energy。

中间参数采用 256 角点的多线性插值，保留原始角点和变量交互。中间 sDA 是教学近似，不是重新运行采光仿真；未改写原始端点表现。成本为教学点数，不是工程报价：基础38、窗面积最多+12、保温玻璃+10且随窗面积再加最多8、窗套最多+6、外墙/屋顶/地面保温最多+13/+10/+8、高新风+5、热回收最多+18。

Art/build_design_lab.py 和 Art/design-lab.blend 保留八变量的 Blender 构件。src/architecture.ts 复用端点网格，按实际窗墙比和深度改变尺寸，保温层和热回收构件同步变化，约0.4秒过渡；减少动态偏好下立即更新。玻璃和新风保留离散设备选择。几何为教学示意，非精确仿真几何。

## 新手平衡与证据

当前是入门对手：前两轮专注自身，之后偶尔进行有意义的参数反制；会尝试不同自身方案。对手不读取玩家手牌或未来抽牌，在玩家行动前承诺本轮计划。牌库与策略随机流独立，难度选择与手牌选择也使用独立随机流。当前引导行动概率4%、考虑反制概率12%，实际是否出牌仍受手牌、体力和收益约束。AI逐张重新计算剩余体力能完成的行动，比较抽牌、防护、强化占用的体力与设计收益；不再认为自调一次就结束。回能后可继续设计，强化看额外收益。

已删除三类次数状态及旧的六步模拟截断。每次出牌都会减少“手牌数＋剩余额外抽牌额度”，所以功能牌可以连续使用，回合仍会自然终止。

评估重建了两种新手代理：

- random：不预知效果，先均匀选可用手牌，再选合法目标；自身和反制都可用时偏好为70/30，继续消耗剩余合法行动，是盲点压力基线。
- learner：前两轮与 random 完全一致；之后仅记录自己实际打出过的参数牌及其结果，不读取未来方案的仿真收益。依记忆估计变化，仍有40–80%探索，未试过的反向牌不会自动被学会。
- tactical：可精确计算方案并规划攻防，作为熟练策略上限。
- idle：全程不出牌，检查是否存在躺赢。

同费连续出牌版本先做宽窗口与独立验证，见 validation/poc-stamina-wide.json 和 validation/poc-stamina-holdout.json，据结束轮数分布保留40/32/40轮上限。加入“成套方案仅自身”后，使用新种子50001–51000、4策略×3关×1000局，共12000局复核，未调整其他数值；现行结果见 validation/poc-glass-self-only.json。

| 模拟策略 | 采光关胜率 | 能耗关胜率 | 成本关胜率 |
|---|---:|---:|---:|
| 盲点压力基线 | 32.80% | 40.70% | 36.70% |
| 从自己出牌结果学习 | 68.40% | 57.10% | 62.00% |
| 熟练规划攻防 | 97.70% | 96.70% | 96.40% |
| 全程不操作 | 0% | 0% | 0% |

盲试平均9.7/5.7/8.5轮，中位数7/4/6轮，超时1.3%/0.4%/1.3%；学习代理平均8.0/5.0/7.3轮，超时不超过0.1%。盲试约40%的回合连续自调两次，约8%的回合连续反制两次，约11%的回合使用三张以上功能牌；仍出现合法七张连用。首轮落败有5.2%/6.6%/2.1%，熟练者仍较容易获胜，需在真人试玩观察节奏。代理有精确记忆，不能把这些数字称为真人新手胜率。报告保存规则快照、体力规则、AI参数、观察上限和源码哈希。旧 poc-stamina-*、poc-novice-*、poc-iteration-*、poc-holdout.json 与 stamina-risk-probe.json 作为迭代历史保留，不代表现行规则结果。

玻璃限制前的同费版本曾把双方临时设为熟练攻防策略，做1500局反复干扰压力检查，历史记录见 validation/stamina-tactical-stress.json。这项检查不改变试玩中的入门对手。

## 代码边界

- src/model.ts：唯一参数、卡牌、成本、仿真插值、关卡和评分定义。
- src/game.ts：不可变状态、统一参数操作与事件、功能牌、回合、AI和新手策略。
- src/main.tsx / src/style.css：卡牌交互、对手反馈、事后变化与历史。
- src/architecture.ts / src/BuildingView.tsx：参数化 Blender 构件、渲染和资源释放。
- scripts/poc-test.mjs：256角点、2916×16转换、双方玻璃仅自身、23328个普通/强化干扰不改玻璃案例、连续同费设计、三张功能连用、七张连招、回能后继续设计、防循环、边界、成本、防护、隐私、新手及900局守恒检查。
- scripts/poc-balance.mjs：可复现平衡模拟；scripts/poc-ui.mjs：实际浏览器全局对局与多屏幕检查。

旧六关、槽位、固定性能增益及旧测试已退出活动代码。原有历史资源保留，构建只复制所需场地、人物、光照及新设计模型。
