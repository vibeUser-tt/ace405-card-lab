# ACE405 建筑竞标实验室

学生与有限状态机对手竞标同一建筑设计委托的 Web 卡牌原型。原来的“余烬之塔”两场打怪系统已替换为建筑性能指标、措施卡、功能卡和单人对抗流程。每个关卡对应课程周次与不同的目标函数；没有学生之间的对战。

## 运行

需要 Node.js 20.19+ 或 22.12+。

```powershell
cd ace405-card-lab
npm install
npm run dev
```

打开终端给出的本地地址，通常为 http://127.0.0.1:5173/。运行 `npm run build` 构建静态网页；运行 `npm test` 执行规则测试和固定种子模拟。桌面与手机浏览器交互测试脚本为 `node scripts/ui-smoke.mjs`，需本地 Vite 服务、Playwright 与 Chrome。

## 发布到 GitHub Pages

这个 `demo` 目录是独立仓库的根目录。仓库的 `main` 分支推送后，`.github/workflows/deploy.yml` 会构建 `dist` 并发布。Vite 使用相对资源路径，因此普通项目仓库和 `<用户名>.github.io` 仓库都可使用。

1. 在 GitHub 创建空仓库，不勾选初始化 README、`.gitignore` 或 License；将本目录推送到 `main`。
2. 在仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
3. 等待 **Actions → Deploy to GitHub Pages** 成功后，从 Pages 设置页打开网站。普通仓库地址为 `https://<用户名>.github.io/<仓库名>/`。

GitHub Pages 是公开网页。当前游戏记录只保存在访问者自己的浏览器中，不会跨设备同步。

## 3D 战场与手机适配

主界面采用单个 Three.js Canvas，双方各有一栋程序化建筑。六类装置对应窗、外墙、遮阳、屋顶布局、材料表皮和系统设备；24 张措施牌都有对应模型变体。热回收有双路气流，夜间通风有通风口，按需控制有控制面板，采光联动照明有灯带。方向光、半球光和阴影提供体积感。方向光以双方建筑区域中心为目标，绕场景竖直 Y 轴约每 60 秒旋转一圈，保持高度不变，阴影随时间缓慢移动；不会转动建筑或改变性能指标。横竖屏布局变化后会重算环绕中心，后台暂停并避免返回时突然跳光，减少动态效果偏好下保持静止。

Y 轴朝上。左右拖动任一建筑区域时，只旋转该建筑的 Y 轴；横向位移除以该侧区域宽度再乘 2π 得到角度变化，竖向位移不改变角度。鼠标与触摸共用 Pointer Events，拖动超过 5px 后不会再触发装置点选。两边朝向独立保存，出牌重建模型和横竖屏切换均保留朝向。安装、反制、增益和护盾的粒子目标每帧从部件局部坐标转换到当前世界坐标，飞行中继续旋转也能跟随；裂纹、护盾网格与气流随建筑一起转动。

安装牌触发装配粒子；反制从手牌位置飞向目标部件，命中后出现碎片、冲击环和本轮裂纹标记；护盾显示保护网格。模型是教学示意，性能指标仍由规则模型计算。点击 HUD 可查看原始值、评审值和权重；点击建筑装置可选取增益或反制目标。

布局根据 `visualViewport` 的实际宽高调整。窄长卡牌下方是结束回合，上方是紧凑出牌操作条：装置牌分别用“装到自己”和“反制对手”直接执行，不需要第二次确认；不可用时按钮变灰并显示体力、预算、次数、同名装置等原因。功能牌使用“打出这张牌”。槽位上行显示装置名，下行始终显示“窗 / 围护 / 遮阳 / 平面 / 材料 / 系统”，空槽显示“未安装”。同槽位换装按钮显示“替换现有装置”，手牌标题旁预告旧→新及预算变化，模型播放拆卸碎片与安装粒子。优化、干扰和护盾通过点击建筑槽位选择措施，可用槽位呼吸高亮，选中后以金色勾选标记显示；只在操作条选择指标。切换措施会清空指标选择，取消或成功出牌后清除高亮，减少动态效果偏好改用静态高亮。灰牌原因、路线和选目标提示统一在“手牌 · 第 N 轮”旁显示。聚焦筛选和保留备选仍直接点选手牌，不打开面板。短横屏按 HUD 与槽位之间的可用空间调整模型显示，避免遮挡。窗口调整、旋转和浏览器工具栏改变可用高度时会重新计算，并保留当前局与所选目标。界面预留刘海与底部手势安全区。

32 张牌均有成功出牌反馈。玻璃、围护、遮阳、布局、材料与系统的安装粒子使用不同形状和颜色，装置从目标位置组装出现；反制命中对应部件。八种功能牌分别显示抽牌、弃抽、体力、保留、增益、干扰、强化与护盾反馈。保留标记与待用反制强化持续显示，粒子落点按出牌后布局计算；未满足条件的牌不播放成功特效。减少动态效果偏好会关闭飞行粒子，保留文字结果。

`npm run test:ui` 要求本地 Vite 服务、Chrome、Playwright 与支持 TypeScript stripping 的 Node（当前测试为 Node 24）。视口覆盖 568×320、667×375、740×320、844×390、932×430、1024×768、1440×900，以及 360×640、390×844、430×932；检查按钮位于手牌上方且不与建筑区域相交、操作按钮在屏内、旋转后选择不丢失、模拟安全区、32 张牌特效及全部模型变体。`complete-games.mjs` 用触控事件在 667×375、844×390、390×844 各从开局打完两局，覆盖安装、同槽换装、同名反制、功能牌与完整结算。这些固定种子整局样例用于交互回归，不是平衡性胜率估计。测试使用桌面浏览器模拟触控视口，实际手机 GPU 性能及 iOS 应用内浏览器仍需真机体验。

## 每局如何玩

1. 选择课程关卡，阅读四项指标门槛、预算上限与公开权重。
2. 每轮抽 5 张牌、获得 3 点基础体力；安装至多 1 张措施、反制至多 1 次、使用至多 2 张功能牌。体力牌可将本轮体力提升到 5。
3. 措施卡可以装到自己的方案。同槽位允许换成不同装置：消耗新牌体力，占用本轮一次安装；旧装置永久移出本局，不进入弃牌堆，其增益、压制和护盾同时清除。相同装置不能重复安装。预算按最终方案重新计算，扣掉旧装置并加入新装置，同时重算联动。对手遵守相同规则，并能通过换装应对压制。如果对手已经安装同名措施，也可以消耗这张手牌反制对手一个**有正向边际收益的指标**。同名反制削减该收益 50%，通用反制牌削减 25%。反制牌从本局移除。
4. 状态机在学生行动前公开本轮意图。它只使用自己的手牌、双方公开方案和公开目标函数，按 SECURE → PRESSURE → BUILD → REFILL 的优先级作决策。
5. 结束回合时，对手执行行动，然后双方同时评审。先通过全部四项性能门槛与预算门槛的一方获胜；同轮都通过时比较公开加权分、再比较预算；仍相同则平局。
6. 每局结束有回合复盘，并按本关开放槽位并排列出“你的方案”和“对手方案”的最终装置、未安装槽位、预算、永久优化及结算当轮压制；已拆除的装置不列入最终方案。课程关卡均可从入口选择；本地浏览器会记住各关卡最快的**达标**轮数。平局仍表示学生方案达标，但不算竞标胜利。游戏成绩不替代课程作业评价。

八种功能牌分别负责抽牌、弃抽、补体力、保留手牌、放大己方边际收益、通用压制、强化下一次压制和抵挡压制。早期关卡开放基础牌，后续按课程周次增加牌种。第一关使用下述教学卡池；其他关卡从已开放的槽位抽取两种设计措施，并混入一条至少存在理论可行解的设计路径；功能牌混入 8 张。W4 起保证有一张通用反制牌，W5 起再保证一张防护牌；通用反制消耗 1 点体力。整局牌组至多 20 张，双方牌组内容相同但各自独立洗牌；牌堆耗尽后循环弃牌。24 张措施卡与功能牌配置在 `src/course-config.json`；核心规则在 `src/game.ts`。玩家可查看本局牌组及“安装后仍有几条可达标路线”；路线考虑换装、已移除的牌和剩余安装轮次，不保证抽牌时机，计入已获得的永久优化，不预支尚未打出的优化牌或当轮减益。状态机也只用自己的牌组、手牌与公开方案规划可行路线。

## 第一关：采光教学关

第一关固定使用六张装置：适度扩大窗面、大面积窗面、固定外遮阳、可调外遮阳、浅进深布局、高反射内表面。双方牌组构成仍相同；学生起手保证两个不同槽位的可配合达标装置，以及一张“保留备选”，其余牌随机。发牌只交换原牌堆中的牌，不复制牌。先安装一张，再保留另一张，可以把起手优势延续到下一轮。

对手公开第一轮勘察，不安装、不反制、不使用功能牌；第二轮恢复正常决策。因此在该卡池下，对手最早第四轮完成三项装置。学生仍可第三轮获胜；五轮上限、体力和安装次数、同轮比较分数/预算的规则不变。性能门槛仍为 E≤120、D≥70、H≤180、C≤380，预算≤100，不能靠只堆采光或随便结束回合过关。

手牌标题旁显示当前还差哪些指标，选择装置时预览安装后的缺口，长提示可横向滑动。未中标会解释缺口；双方都达标时明确说明输在综合分或预算。后五关不应用教学规则，500 局固定种子对照确认其发牌、对手行动和结算与前一版本完全一致。

七种普通策略不读取对手手牌、隐藏抽牌顺序，也不搜索完整最优解；仅“按提示”使用界面已有的路线计数。这些策略不使用攻击，便于单独检验教学关的安装与保牌节奏。定稿后先用每种 1,000 局检查，再用未参与调参的 10,001–12,000 号种子、每种 2,000 局独立验证；新版共 21,000 局，旧版对照另 21,000 局。原始数据在 `validation/tutorial-training.json` 和 `validation/tutorial-holdout.json`。

| 策略 | 旧版获胜 | 教学版获胜 | 教学版平局 |
| --- | ---: | ---: | ---: |
| 随机选可安装装置 | 9.95% | 24.65% | 6.55% |
| 只增加采光，不顾其他门槛 | 1.10% | 0% | 0% |
| 优先随机填空槽，再按缺口换装 | 21.20% | 65.10% | 10.15% |
| 优先减少当前指标缺口 | 15.65% | 73.40% | 12.30% |
| 补短板，但 20% 的选牌随意 | 17.25% | 64.05% | 10.85% |
| 补短板，但错过第二轮安装 | 2.80% | 25.45% | 15.40% |
| 补短板并避开无可行路线的牌 | 15.80% | 73.45% | 12.35% |

这是脚本代理人的胜率，不是真人学生数据。随机选择仍明显更难赢，错过整轮仍会付出代价；保底起手不会保证获胜。测试脚本可用 `node scripts/tutorial-balance.mjs --runs=2000 --offset=10000` 复现。`npm test` 另验证 1,000 次起手的配套装置/保留牌、卡牌守恒、首轮勘察和不操作不能获胜。

## 为什么是 5、6、8 轮

| 关卡 | 上限 | 原因 |
| --- | ---: | --- |
| 采光、前期碳 | 5 | 目标通常靠 2–3 个关键因素形成可行方案；再给抽牌与反制空间。 |
| 能耗 | 6 | 需要兼顾采光和过热的副作用，给 1 轮额外缓冲。 |
| 采光与过热、综合设计、最终综合 | 8 | 六个设计槽位最多每轮安装一个；另外两轮容纳找牌、体力与攻防取舍。 |

这些都是**上限**，一方先达标会提前结束。换装规则加入前的版本用五种模拟策略、两批各 1000 个独立种子/关卡测试；规划型玩家的结束轮数中位数为采光 3、能耗 3、前期碳 4、采光与过热 5、综合 5、最终 5。复杂关卡第 90 百分位为 7 左右。模拟不能代表课堂耗时；真人试玩后还需按每轮思考时间和“无有效决策”的比例调整。

## 可玩性调参与模拟结果

聚焦优化现已改为永久增益，以下旧版及换装版的后期关卡胜率是历史结果。第一关没有聚焦优化牌，教学关数据仍对应当前规则。

以下 60,000 局表格为**禁止同槽换装的旧版基线**，不能直接作为当前版本胜率。第一关已进一步改为上述教学规则，旧表及换装回归不再代表当前第一关。换装版已经更新脚本的方案替换、路线筛选与对手意图预测逻辑，并另做两种策略各 200 局/关、共 2,400 局回归；结果记录在 `validation/replacement-balance.json`。脚本策略不等于真人学生。

目标是让**会规划并择时使用反制的玩家**在每关仍可能输，模拟胜率约 45%–65%；只看眼前数值的策略应明显更难赢。随机、眼前收益、新手按提示、规划路线、规划加攻防五种策略，在两个不重叠的随机种子批次上各打 1000 局/关，共 60,000 局。下表是第二批的**玩家获胜比例**，平局另算：

| 关卡 | 随机 | 只看眼前 | 按可行路线提示 | 规划路线 | 规划＋攻防 | 规划＋攻防平局 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 采光 | 13.4% | 27.6% | 33.7% | 42.9% | 50.7% | 27.6% |
| 能耗 | 6.5% | 18.2% | 36.2% | 45.6% | 53.2% | 5.2% |
| 前期碳 | 4.1% | 22.4% | 36.9% | 45.4% | 54.4% | 1.2% |
| 采光与过热 | 4.1% | 13.9% | 30.1% | 46.1% | 56.7% | 3.9% |
| 综合设计 | 5.7% | 17.0% | 32.7% | 47.5% | 58.4% | 2.1% |
| 最终综合 | 3.1% | 11.1% | 36.4% | 46.3% | 57.1% | 3.4% |

这两个批次的每个策略/关卡胜率差至多约 3.4 个百分点。后期关卡的攻防策略每局平均打出约 0.28–0.33 次反制，对手公开 PRESSURE 意图约 0.47–0.63 次；两边合计接近每局一次攻防机会。采光入门关的完全相同方案仍会产生较多平局，因此平局会记录为“设计达标”，但不算竞标胜利。

上述策略都是脚本代理人：随机策略乱选，眼前策略只看当前缺口，提示策略会避开使可行路线归零的措施，规划策略从可用卡组找可达标组合，攻防策略还会择时抽牌、保牌、增益、反制与防护。它们不是学生能力分组，也不能证明真人会觉得好玩。真人试玩应记录胜率、平均决策时间、误解指标的次数、主动反制次数和重开原因，再调整卡池与状态机。两批原始结果保留在课程研究工作区，未包含在这个独立演示仓库中。

## 数值来源与边界

四项代理指标为 E（能耗）、D（采光）、H（过热小时）、C（A1–A5 前期碳），基准分别为 100、45、160、300。24 张措施卡的增量、四组交互效应和关卡权重来自课程研究工作区先前建立的**合成教学算例**；试玩后调整了采光、能耗、前期碳关的门槛（以 `src/course-config.json` 为准）。它们不是 M-huset 的实测值、仿真结果或合规标准。预算 100 是游戏点数。课程任务书中的扩建面积上限 1500㎡是课程约束；本代理模型并不生成几何。

正向边际收益按 `F(当前方案) − F(移除该措施后的方案)` 计算，包括措施间交互。聚焦优化对指定装置的指定有利指标永久 +25%（本局内），换轮保留；同装置同指标不能叠加，不同指标可分别优化。拆除旧装置会清除其优化，新一局不继承。压制只持续当轮。二者修正**竞标评审值**，不篡改界面显示的原始物理代理值。E/H/C 越低越好，D 越高越好。加权分使用固定归一化：E 对应 120→50、D 对应 30→80、H 对应 200→50、C 对应 400→200，指标分限制在 0–100；门槛必须先全部通过，分数只做同轮达标时的裁决。

进入真实课程项目时，需用同一基准模型和课程工具重新标定卡片增量与交互；保留来源、单位、工况和不确定性。当前数值只用于测试“不同委托下该看哪些因素和指标”的玩法。

## 验证

永久优化回归：`scripts/permanent-buff.mjs` 验证连续换轮、同指标封顶、不同指标分别优化、临时压制到期、双方规则一致、拆除/新局清理，以及带优化的可行路线。`scripts/permanent-buff-ui.mjs` 在 568×320、844×390、390×844 和 1440×900 实际点击优化并连续换轮，核对 HUD 数值、标记和换装。两种规划策略各 200 局/关、共 2,400 局的规则回归结果见 `validation/permanent-optimization-regression.json`，新增了永久优化不能重复叠加的断言；这不是一次新的真人难度标定。

`npm test` 先检查换装体力与次数、预算返还、旧联动移除、压制/增益/护盾清理、旧牌不循环、剩余路线和 NPC 换装防御，再检查六关均有理论可行解、预算不超标、交互被计入边际收益、反制只改变评审值、体力牌与同名反制的行为、200 个固定种子下每关均能在上限内结束。`node --experimental-strip-types scripts/playability.mjs --runs=1000` 会运行五种模拟玩家策略，每关各 1000 局并检查预算、槽位、手牌、体力与轮数不变量。浏览器脚本检查 1920px、1366px 与 390px 视口能进入关卡、查看牌组、选择手牌、结束回合，且无运行错误和横向页面溢出。
